## 2. 冻结的几何契约（要点）

- **平面布局**：`stride = align_pow2(plane_visible_width, 32)`（字节），`aligned_height = align_pow2(plane_visible_height, 32)`；三平面**一次 `calloc`**，帧级唯一分配，无 per-block malloc、无对象池。
- **尺寸合法性**：可见宽/高必须为非零且为 8 的倍数，否则 `SVT_AV2_ERROR_UNSUPPORTED`；零值返回 `SVT_AV2_ERROR_INVALID_PARAMETER`。
- **坐标系**：全模块只用**平面相对**单一坐标系，不存在 block-relative 第二套约定。`has_left = (x > 0)`，`has_above = (y > 0)`。
- **色度**：坐标为截断半化 `x >> 1` / `y >> 1`；形状查 `Subsampled_Size` 表（`8x8→4x4`、`16x16→8x8`、`32x32→16x16`、`64x64→32x32`、`64x32→32x16`、`32x64→16x32`），**不是** `w/2 × h/2`。
- **边界隐含划分**：沿用 AVM `is_partition_implied_at_boundary` 的 `hbs` 判据，隐含划分**不产生语法符号**。

## 7.1 U2 已关闭：边界隐含划分不读语法符号（规范正文证据）

规范 `AV2_Spec_v1.0.0_20260528_38f28e7.pdf` §5.20.3.2 `read_partition(r, c, bSize, ...)`：

```
(implied, partition) = partition_implied(r, c, bSize)
(numAllowed, allowed) = init_allowed_partitions( r, c, bSize, chromaOffset, hasChroma )
if ( implied && allowed[ partition ] ) {
    return partition          <-- 直接返回，未读任何 f()/S()/L() 描述符
}
```

`partition_implied(r, c, bSize)`（同节）：

```
if ( bSize == BLOCK_4X4 || bSize >= BLOCK_4X32 ) return (1, PARTITION_NONE)
if ( TreeType == CHROMA_PART && bSize == BLOCK_8X8 ) return (1, PARTITION_NONE)
if ( TreeType == CHROMA_PART && bSize == BLOCK_64X64 && ChromaPartitionKnown[r][c] )
    return (1, LumaPartitions[r][c])
return partition_implied_at_boundary(r, c, bSize)
```

**结论**：当 `partition_implied` 判定为隐含时，`read_partition` 立即返回该划分，
`do_split` / `do_square_split` / `rect_type` / `do_ext_partition` 等描述符都在其**之后**
（位于 `bru_mode != BRU_ACTIVE` 分支内），**不会被读取**。T007 的既有实现（边界子块直接上报、
不递归、不产生符号）与规范一致，无需修改。

### 7.2 核对 `partition_implied_at_boundary` 公式与实现一致

规范原文（§5.20.3.2）：

```
numWide4x4 = Num_4x4_Blocks_Wide[ bSize ]
numHigh4x4 = Num_4x4_Blocks_High[ bSize ]
hasRows = ( r + (numHigh4x4 >> 1) ) < MiRows
hasCols = ( c + (numWide4x4 >> 1) ) < MiCols
if ( hasRows && hasCols ) return (0, PARTITION_NONE)
impliedPartition = PARTITION_NONE
if ( numWide4x4 == numHigh4x4 ) impliedPartition = hasRows ? PARTITION_VERT : PARTITION_HORZ
...
```

- `numWide4x4 >> 1` 即 hbs：`Num_4x4_Blocks_Wide[BLOCK_64X64] == 16`，故 64 SB 的 hbs = 8 mi，
  与本模块 `sb_mi / 2` 相同。
- 真值表（方形块，只有三行可达，因为 `(1,1)` 已提前返回 NONE）：

| hasRows | hasCols | 规范 | 本实现 | |
|---|---|---|---|---|
| 1 | 1 | NONE | NONE | 一致 |
| 1 | 0 | VERT | VERT | 一致 |
| 0 | 1 | HORZ | HORZ | 一致 |
| 0 | 0 | HORZ | HORZ | 一致 |

- `partition_implied` 的 `bSize >= BLOCK_4X32` 守卫**不适用于本轮**：block size 枚举中
  `BLOCK_64X64` 位于 `BLOCK_4X32` **之前**（`avm av2/common/enums.h:398` vs `:411`），
  故 64×64 不落入该守卫。
- 已按上表在 `test_block_geometry.c` 中补齐 `(0,0)`、`(1,0)`、`(0,1)` 三种边界组合的断言
  （用 160×160 / 64 SB 构造：mi 40×40，sb_col=2 跨 mi[32,48)，32+8=40 不 < 40）。

规范证据原文已落盘：`artifacts\T007\spec-partition-evidence.txt`。

### 10.6 图像存储与生命周期

```c
SvtAv2FrameBuffer pic;           /* 库拥有的帧存储，与 include/svt_av2.h 的
                                  * SvtAv2Picture（调用方借出的输入视图）**不是**同一类型 */
svt_av2_picture_alloc(&pic, width, height);   /* 一次 calloc，帧级唯一分配，无 per-block malloc */
svt_av2_picture_pad(&pic, 128);               /* 幂等；只写 padding 区，绝不触碰可见样本 */
svt_av2_picture_copy_in(&dst, &src);          /* 逐行 memcpy；调用期读取，**不保留**外部指针 */
svt_av2_picture_export_raw(&pic, out, cap, &size);  /* 紧凑 Y‖U‖V，**移除全部 padding** */
svt_av2_picture_free(&pic);                   /* 幂等，可对已 zeroed 描述符调用 */
```

| 项 | 冻结值 / 语义 |
|---|---|
| 布局 | `stride = align_up(plane_visible_width, 32)` 字节；`aligned_height = align_up(plane_visible_height, 32)` 行 |
| 分配 | 三平面**一次** `calloc`（帧级唯一分配）；无对象池、无 per-block malloc |
| 所有权 | 库拥有所有 buffer；`svt_av2_picture_free` 释放 |
| 对齐承诺 | 仅标准 malloc 对齐；**不承诺**任何 SIMD 对齐 |
| 样本类型 | `uint8_t`；stride 单位为字节（8-bit 下等于样本数，10-bit 起不等） |
| 可见尺寸合法性 | 非零且为 **8 的倍数**；否则 `SVT_AV2_ERROR_UNSUPPORTED` |
| export_raw 长度 | `W*H + 2*(W/2)*(H/2)`；容量不足 → `INVALID_PARAMETER`，**不写部分数据** |
| export_raw 复用 | **source 与 recon 共用这一个导出原语**，T012/T013 不得另写第二份拷贝 |
| source/recon 区分 | 两个**独立**缓冲；由调用方决定往哪个写、导出哪个。本模块不区分，但禁止把 source 当 recon |
| 调用方责任 | `strides[plane]` **不能**用于推断外部缓冲长度；本模块不探测指针容量 |

### 10.7 调用方各自的最小用法

- **T008（预测）**：`svt_av2_block_view(&geo, &recon, plane, sc, sr, &blk)` → 取块；
  `svt_av2_block_neighbors(&recon, plane, &blk, &nb)` → 取邻居；不可用邻居的替代值按规范自行决定。
  **预测输出必须写回同一 stride 的 picture 布局**（契约 §2.1）。
- **T012（重建）**：**`svt_av2_partition_traverse` 的回调只给几何，`base` 恒为 NULL**；要拿像素地址必须在
  回调内用 `svt_av2_block_view(&geo, &pic, plane, sc, sr, &blk)` 再取一次（该重载才填 `base`），
  或自行计算 `plane + y*stride + x`。系数链结果 clip 到 `[0,255]` 后写回。
  导出用 `svt_av2_picture_export_raw`，**不要**自己拼 raw。
- **T013（输入接线）**：`svt_av2_picture_copy_in(&internal_src, &caller_src)` 在 `send_picture` 调用期内完成；

> **注意（易错点）**：`svt_av2_block_from_sb` / `svt_av2_partition_traverse` 产出的视图 `base` 恒为 `NULL`
> （前者不接收 picture，后者传 `NULL` 给子块）。需要 `base` 时**必须**用接收 picture 的

### 11.2 第 1 条的修法（第一版修错了，如实记录）

- **第一版（错误）**：`(size_t)plane_height > SIZE_MAX - 31`。GCC **再次**报 `-Wtype-limits`——
  `SIZE_MAX-31` 仍大于任何 `uint32_t`，**加个强转并不能改变右操作数超出左操作数值域**这一事实。
- **最终修法**：在 `uint32_t` 值域判定 align_up 是否进位（`align_up(v,32) == (v+31)&~31`，
  仅 `v > UINT32_MAX-31` 时回绕）：

```c
if (plane_width  > UINT32_MAX - (SVT_AV2_PICTURE_ALIGN - 1u) ||
    plane_height > UINT32_MAX - (SVT_AV2_PICTURE_ALIGN - 1u)) {
    return SVT_AV2_ERROR_INVALID_PARAMETER;
}
```

该判定在 32/64 位目标上都非恒真亦非恒假，保护语义比原写法更强。

GCC 报 `"/*" within comment [-Werror=comment]`。该处注释**从未闭合**，把 285–290 行吞成注释体，

修复后 **197 → 202 checks**（5 条断言恢复），仍 0 failures——**覆盖率真实增加**。已顺带核对六个
T007 文件的 `/*` 与 `*/` 计数，全部配平。

### 11.4 额外发现 B：巨额 `calloc` 请求令 ASan abort

San 配置下 `test_picture` abort，`requested allocation size 0x6000000000000000`。
精确算术：`0x80000000 x 0x80000000` 的 4:2:0 总量为 `0x6000000000000000`（6.9 EiB），
**不溢出 `size_t`**——原"只查回绕"的守卫**算术上正确地判定无溢出**。

**错的是判据**：`size_t` 装得下 ≠ 任何人能分配。libc 的 `calloc` 会返回 NULL，但 ASan 对超大
请求**直接 abort**，"不可能满足的请求"于是从可观测错误变成崩溃。

**修法**：加显式上限 `max_total = (size_t)1 << 34`（16 GiB），超出即 `OUT_OF_MEMORY` 且**不调用分配器**。
该上限远高于任何目标尺寸（1080p 4:2:0 约 3 MiB），又小到足以保证请求总是真实可失败的分配。
边界核验：64×64 / 176×144 / 720p / 1080p / 8192² 全通过；`0x80000000²` 被拒绝。
`test_picture.c` 的"合法但巨大"用例由 `65536×65536`（6 GiB，仍超 ASan 分配器上限）改为
`8192×8192`（96 MiB），并**新增**一条断言要求 `0x80000000²` 返回 `OUT_OF_MEMORY`。
`test_picture` 检查数 30836 → 30837。

### 23.5 方法学：陈旧产物陷阱（可复现判据，00 已采纳）

**判据（可复现）**：核对任何产物（二进制/exe/符号表）前，先确认
**该产物 mtime ≥ 其对应源码 mtime**；不满足即判为陈旧，不得用作证据。

```powershell
# 陈旧的判定：产物 mtime 早于源码 mtime 即不可信
```

**实例三（同族，且这次错方是 T007）：`Select-String -Path <dir>\*` 不递归，会伪造"符号不存在"。**
T007 曾断言"`svt_av2_enc` 在源码树零命中（尚未存在）"，依据命令为
`Select-String -Path Source\Lib\* -Pattern "svt_av2_enc"`。T013 指正后实测复核：**T007 主张错误**。

**根因更正（T007 首次归因错误，T013 隔离变量后更正，T007 已逐条复现确认）**：
T007 最初把零命中归因于"`-Include *.c,*.h` 排除了 `CMakeLists.txt`"。**该归因是错的**——
T013 逐变量隔离，T007 复现，实测三组：

```powershell
(1) Select-String -Path Source\Lib\* -Pattern "svt_av2_enc"                      # ->  0 命中
(2) Get-ChildItem -Recurse -File Source\Lib | Select-String -Include *.c,*.h `
        -Pattern "svt_av2_enc"                                                   # -> 17 命中
(3) Get-ChildItem -Recurse -File Source\Lib | Select-String -Pattern "svt_av2_enc" # -> 42 命中
```
**关键对比 (1)=0 vs (2)=17**：若真因是 `-Include` 排除了 `CMakeLists.txt`，则 (2) 也应为 0；
**(2)=17 证伪该归因**。(1) 与 (2)/(3) 的**唯一差别是递归** —— `Select-String -Path <dir>\*`
**不递归**，只扫 `Source\Lib` 这一层、不进 `Codec/` 等子目录，而 `svt_av2_enc` 定义在
`Source\Lib\Codec\CMakeLists.txt:9`（`add_library(svt_av2_enc STATIC`）——**在子目录里**。
→ **零命中的真因 = 缺递归**。

附注（亦经 T007 实测）：`Select-String` **没有 `-Recurse` 参数**（实测报
`NamedParameterNotFound`）；要递归必须 `Get-ChildItem -Recurse | Select-String`。

**连带更正**：T007 同批还写过"`encoder.c` 内不含该字符串"——**亦反了**：实测
`Select-String -Path Source\Lib\Codec\encoder.c -Pattern "svt_av2_enc"` = **13 命中**。
正确的说法是：`add_library(svt_av2_enc …)` 的**定义**只在 CMake，但该**字符串本身**在 `.c` 里
也有（如 `#include "svt_av2_enc.h"`）。T007 由"零命中"反推"只定义在 CMake"，**前提已错，结论随之错**。

**修正版纪律（替换 T007 原归因）**：检索仓库符号时，`Select-String -Path <dir>\*` **不递归**。
要全树检必须 `Get-ChildItem -Recurse -File <dir> | Select-String -Pattern <sym>`；
必要时应**不加** `-Include`（或把 `CMakeLists.txt` 等其它扩展名一并列入），否则会
**伪造"不存在"的结论**。**不要记成"`-Include *.c,*.h` 的错"——那是次要因素，真因是递归。**
```powershell
# 错（不递归，漏子目录）：只扫本层
Select-String -Path Source\Lib\* -Pattern "<符号>"
# 对（递归全树）：
Get-ChildItem -Recurse -File Source -Include *.c,*.h,*.txt | ForEach-Object {
    Select-String -LiteralPath $_.FullName -Pattern "<符号>" }
```
