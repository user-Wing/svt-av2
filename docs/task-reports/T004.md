## 4. 字段序（与 AVM 解码器交叉核对）

写入顺序与 `avm/av2/decoder/obu.c:541–611`（`read_sequence_header_obu`）逐字段一致：

```
seq_header_id uvlc

single_picture_header_flag f(1)          # =1
seq_level_idx f(5)
  # single_picture => seq_tier 不写（推断 0）

bit_depth_idc uvlc                        # 1 (8-bit)
  # single_picture => 不写 seq_lcr_id/still_picture/max_tlayer_id/max_mlayer_id/monotonic

frame_height_bits_minus_1 f(4)

max_frame_height_minus_1 f(height_bits)
seq_cropping_window_present_flag f(1)     # =0
  # single_picture => 不写 display delay / decoder model
sequence_partition_config()               # 5.4.3
sequence_segment_config()                 # 5.4.4
sequence_intra_config()                   # 5.4.5
sequence_inter_config()                   # 5.4.6（single_picture 分支）
```

## 5. 测试

独立核对方式（两层，避免与实现共享同一误解）：
1. 按规范语法另写一份 Python 参考模型生成期望字节；
2. C 单测把 writer 输出与固定向量逐字节比较，并经 T003 `svt_av2_obu_write()` 走完整 OBU framing。

向量（`profile=0, single_picture=1, level=0, 420, 8-bit`，经 `payload_finalize` 后的 payload）：

| 尺寸 | level | payload（十六进制） |
|---|---|---|
| 176×144 | 0 | `82 0A 77 AF 8F 00 00 40 01 00 00 80` |
| 64×64 | 0 | `82 0A 55 FF F0 00 04 00 10 00 08` |
| 352×288 | 1 | `82 1A 88 AF C7 C0 00 10 00 40 00 20` |
| 1920×1080 | 4 | `82 4A AA EF F0 DC 00 01 00 04 00 02` |
| 640×360 | 1 | `82 1A 98 9F EC E0 00 08 00 20 00 10` |

OBU framing 校验（176×144）：`0D 04 82 0A 77 AF 8F 00 00 40 01 00 00 80`（`0x0D`=leb128(1 header+12 payload)，`0x04`=header `0|00001|00`）。

覆盖：`uvlc`/`ns` 已知向量；`seq_header_id`/`profile`/`level` 边界（含 level 22..30 拒绝、31 通过）；尺寸位宽（64/176/352/640/1920）；`NO_SPACE`；非对齐拒绝；NULL；默认配置。`seq_tile_info_present_flag=1` 明确返回 `UNSUPPORTED`（`tile_params()` 不在 M1 子集）。

结果：`test_sequence_header: 74 checks, 0 failures`；Release 与 Debug 全新构建 exit 0，CTest 11/11 Passed。

### no_space 口径（契约 §5）

`svt_av2_sequence_header_write()` 由多次 `BitWriter` 原语组合而成，**不做整段容量预检**，因此不是整段原子。契约 §5 只要求 BitWriter 原语与 `svt_av2_obu_write()` 原子。单测据此：
- 小缓冲（4 B）只断言返回 `NO_SPACE`，不断言 `bits_written==0`；
- 用容量 0 的 counting writer 验证“首个原语即失败、`bits_written==0`”的 no-partial-write 保证。

## 7. M1 sequence-header 入参建议（已发 T005，抄送 00）

以下为 T004 依规范给出的明确取值建议（对应 `SvtAv2SequenceHeaderConfig`，结构已存在，无需新增入口）：

| 入参 | 建议值 | 依据 |
|---|---|---|
| `seq_header_id` | 0 | uvlc，< `MAX_SEQ_NUM`=16（§5.4.1） |
| `seq_profile_idc` | 0 | Table A.1 Main_420_10_IP0（400/420，bit_depth_idc 0/1） |
| `single_picture_header_flag` | 1 | §5.4.1 单帧最简路径 |
| `max_frame_width/height` | 64×64 | 4096 samples，单 SB/单 tile，最小块路径最简 |
| `use_256x256_superblock` / `use_128x128_superblock` | 0 / 0 | SB=64×64（`get_seq_sb_size()`），恰 1 个 SB |
| `seq_tile_info_present_flag` | 0 | §5.4.2 不写 `tile_params`，解码器派生单 tile |
| `seq_level_idx` | 0 | Table A.8：level 0=2.0，MaxPicSize 147456、MaxH/V 640；64×64 在限内，为覆盖该尺寸的最小合法 level（最低即 2.0） |
| `seq_tier` | 不写（推断 0） | §5.4.1：single_picture 不写 |

派生位宽（写入口自动计算）：64×64 → `frame_width/height_bits_minus_1`=5（num_bits=6），`max_frame_width/height_minus_1`=63。

`base_q_idx`（帧级，T005 归属）：`f(n)`，`n=BitDepth==8?8:9`，8-bit 合法范围 [0,255]（`MaxQ=MAXQ_8_BITS`）；sequence header 不写，建议值由 T005 在帧语法确定。
