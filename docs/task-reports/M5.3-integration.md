## 本轮开发

用户将多QP提前，后续模式只保留CQP和CRF，取消CBR、2-pass、VBR/VBV独立码率模式。用户目标是主流视频质量与体积的综合控制，不将未经测量的“最佳”作为已有事实；CRF仍属M9，本轮没有别名实现。M6完整RD、M7实际preset、M8内部多线程不提前宣称完成。

公开API和CLI支持非无损CQP1..255，默认100。8bit实际qindex=QP，10bit沿用QP+48即49..303，QP0继续拒绝。原三格式AI/P、intra/partition四组合和尺寸上限保持。24种工具/预测结构/格式基本配置×255QP，共6120种；已有preset枚举不对应不同策略，不计入有效组合。

A扩大量化查表到303，修正INT32_MIN绝对值、20bit producer系数范围，以及固定解码器的24bit反量化mask/round/sign和位深clip。独立模型覆盖全部255QP×两位深×TX4/8/16/32/64×YUV及符号/极值，严格MSVC/GCC和sanitizer均30331429 checks、0 failures。未通过降低质量或把QP任意值偷偷映射到100来伪装支持。

B按实际qindex的90/140/190阈值补齐全部四组系数CDF，22类表的原q1/q2值逐项保持；新补q0/q3。10bit跨组的userQP为42/43、92/93、142/143。QP100四组合旧流保持，非无损条件和8/9bit字段合法。独立诊断使用本轮私有目录m53-b，旧诊断副本和固定oracle/spec均保持。

tools/m53_batch.py冻结素材/工具/模型/配置指纹，流式逐帧核对重建并计算原格式Y/U/V PSNR/MSE；成功后清除raw，只保留首流、VMAF JSON、日志和逐帧hash。每次重复重核流/recon，计时用perf_counter，内存为OS采样峰值，未采到为null而非零。

VMAF使用固定Netflix v3.0.0 tag的vmaf_v0.6.1模型，两路转yuv420p10le并重置PTS；不把444色度质量交给VMAF替代，原格式色度PSNR仍报告。模型SHA和FFmpeg可执行文件SHA写入每批manifest。BD-rate至少4个有效点，采用共同质量区间内log码量上的保单调PCHIP，非单调/重复点/无重叠等报N/A。高精度测量768项的288条BD记录中247有效、41 N/A，不能强行把每条曲线拟合成成功。
