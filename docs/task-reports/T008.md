## 2. 假设与规范条款

**唯一规范真值**：AV2 Bitstream & Decoding Process Specification v1.0.0（本机
`docs\spec\AV2_Spec_v1.0.0_20260528_38f28e7.pdf`，SHA256 `E9916F09…B533F`）。本轮**已用 pymupdf 抽取原文**
（不是凭记忆），逐条摘录如下。

| 规则 | 条款 | 实现位置 |
|---|---|---|
| 帧内预测按 **transform block** 调用（非整块一次） | §7.13.2.1 | `SvtAv2IntraBlock` 以 tx 为单位 |
| AboveRow/LeftCol 构造与不可用邻居替代 | §7.13.2.1 | `svt_av2_intra_reference_build_flags()` |
| DC 四分支：both→`Clip1(approx_divide(sum,w+h))`；left only→`Round2(sum,log2H)`；above only→`Round2(sum,log2W)`；neither→`1<<(BitDepth-1)` | §7.13.2.10 | `svt_av2_intra_dc_predict_flags()` |
| `Round2(x,n)=⌊(x+2^(n-1))/2^n⌋`（整数等价式 `(x+(1<<(n-1)))>>n`） | §4.8 eq.(6) | `round2_u32()` |
| `Clip1(x)=Clip3(0,2^BitDepth-1,x)` | §4.8 eq.(2) | `clip1_8bit()` |
| `FloorLog2` | §4.8 | `floor_log2_u32()` |
| `approx_divide(num,den){ (shift,scale)=resolve_divisor(den); return Round2(num*scale,shift) }` | §7.13.2.10 / §7.13.2.11 | `resolve_divisor_u32()`+`approx_divide_u32()` |
| approx_divide 是**近似**除法，结果必须 Clip1（NOTE 原文） | §7.13.2.11 NOTE | both-available 分支的 `clip1_8bit` |

**逐项不可用邻居替代（§7.13.2.1，并与 `avm\av2\common\reconintra.c:1197-1236` 交叉核对）**：

- `haveLeft=1 && haveAbove=1`：读真实邻居 `CurrFrame[y-1][x..x+w-1]` 与 `CurrFrame[y..y+h-1][x-1]`。
- `haveLeft=1 && haveAbove=0`：AboveRow **全部** = `CurrFrame[y][x-1]`（LeftCol[0]）。
- `haveLeft=0 && haveAbove=1`：LeftCol **全部** = `CurrFrame[y-1][x]`（AboveRow[0]）。
- 都不可用：全部 = `1 << (BitDepth-1)` = 128（8-bit）。

可用性判定：`haveLeft=(x>0)`、`haveAbove=(y>0)`。**chroma 与 luma 边界恒等**（T007 v2 §3 已证），
故不引入 chroma 专用字段；但**tile/superblock 边界**不是图像边界，额外提供
`_flags` 入口由 T012 显式传入。

**假设（显式声明）**：

1. 本轮只实现 **DC_PRED**（契约 §0 冻结值）。未实现 V/H/方向/SMOOTH/PAETH/IBP/DIP/CFL；
   未实现 `mrl_index`（多参考行），即恒 `mrl_index=0`、`aboveMrlIndex=0`。
2. bit depth 8-bit、4:2:0。`clip1_8bit` 硬编码 255；10-bit 是 M3，届时需改为按 `BitDepth` 参数化
   （`1<<(BitDepth-1)` 已按此写法）。
3. `w`/`h` 为 2 的幂（transform 尺寸），故 `log2W/log2H` 用 `floor_log2` 得到；
   `Round2(sum,log2H)` 的 n=0 分支已实现但本轮不会走到。
4. 预测只从**内部 recon** 取邻居，绝不从 source；两者是不同缓冲。
5. padding **不**用作"邻居不可用"的替代值（契约 §1.3）；参考样本构造不读 padding。

### 3.1 residual 输出布局（本轮明确的接口决定，需 T012 确认）

原实现把 residual 按**平面坐标**写（`residual[i*stride + block->x]`），而"block-local"（从 0 开始）
是更自然的读法，两者在 `block->x>0` 时结果不同。该歧义在第一次测试中立刻暴露
（323k 失败）。**现冻结为 block-local**：`residual[i*residual_stride + j]`，i∈[0,h)、j∈[0,w)，
`block->x/y` 只决定**读**的位置，不位移输出；`residual_stride` 校验对象是 **block->w**（不是平面宽）。
这正是 T009 变换要消费的布局。已写入头文件注释。

### 4.3 过程中发现并修正的两个真实问题（记录在案）

1. **不可用邻居替代值的"镜像"必须查清方向**。初版实现按直觉写，随后从
   `reconintra.c:1197-1200`（`memset16(left_col, above_ref[0], …)`）确认：
   `haveLeft only` 时 **AboveRow** 被填成 LeftCol[0]，`haveAbove only` 时 **LeftCol** 被填成 AboveRow[0]。
   方向写反会得到看似合理但错误的预测值，且只在"仅上/仅左"时暴露。
2. **`approx_divide` 不是精确除法，不能用 `(sum + den/2)/den` 替代**。
   我最初写的测试模型用了幂等捷径（"den 是 2 的幂"），对**正方形**块成立（`w+h=2w`），
   但对**矩形**块不成立：8×16 → `den=24`、4×16 → `den=20`、32×8 → `den=40`。
   在 den=24、sum=2478 时近似除法给 103，而四舍五入除法给 103… **规范值 103 与朴素除法不同**
   （朴素 `round(2478/24)=103` 巧合相同，但在大量 sum 上系统性偏离约 1）。
   即：**是测试模型错，不是实现错**。已把模型改为真正的
   `resolve_divisor` + `Round2(sum*scale, shift)` 链，并新增
   `test_rectangular_divisor_is_approximate`，它对每个非 2 的幂除数穷举 `sum ∈ [0, 255*den]`，
   断言实现跟随 `resolve_divisor` 而非四舍五入除法，并要求该除数上确实存在分歧（否则测试无意义）。
   这正是任务书"独立模型"要求能抓到的错误。
