日期：2026-10-16。范围：核对网页版 AI 留下的文档、源码和证据，独立重建/抽验，并修订目标；本轮没有开发新的编码工具。

## 1. 当前判断

工作树已具备 **ALL-INTRA 的 Y DC/V/H 实验性自适应模式选择**，不是只有预测器原型。单一选择结果贯穿预测、残差/变换/量化、内部重建及 Y mode set/index、UV DC 条件语法。UV 本身仍选 DC；P 中不能启用 adaptive，初始化会拒绝。决策是 Y SAD，不能据此宣称完整 RD、码率或质量提升。

M5整体仍为 RUNNING。正式已验收产物仍为 M4；工作树虽然版本字符串仍为0.0.4-m4，但公共config已追加字段，不能与旧二进制ABI混用。旧M4产物/最小FFmpeg包不自动获得新功能。

## 4. 目标定义的问题与本轮修订

1. 原README把12个工具族都列入M5，任务表却主要只有V/H与partition，没有其余工具的确切子集和DoD；“全部承诺工具完成”没有可判定边界。
2. 总计划§9.5要求主流AI/RA稳定编码，但本期显式排除B/多参考，现有实现是AI/单参考低延迟P。RA必须有独立参考结构合同，不能成为当前无法实现的隐含门槛。
3. M5应提供合法工具与有界决策，M6才负责完整RD；用多个工具、完整RD、preset/码控同时作为M5门槛会阻塞阶段闭环。
4. G4在README指partition，在验收文档却指跨平台；改为G4=partition、G5=测量、G6=平台与冻结。旧“G1原型”叙述明确标为历史。

**新的0.0.5-m5明确范围**：M5.1=三格式DC/V/H在AI和P intra fallback真实接线；M5.2=一个有明确规范合同的非边界内容可变partition子集；M5.3=两项的组合、完整回归、测量、三格式AI/P长链、跨平台及检测器验收。默认关闭严格保M4，现有QP/线程/尺寸/色度限制保持。

这是主动收敛版本范围，不是声称原12工具族已经实现。其余族保留为后续Core Tools待办，逐项签订feature合同；未来可与M6框架递进集成。RA另立阶段/合同。不得因收敛而降低逐样本一致、真实模式/分区证据、回归和内存安全门槛。

## 5. 下一步优先次序

1. 补模式规范表/独立trace和API专项测试，再接P中intra fallback；覆盖场景切换和真实intra/inter混合。
2. 跑齐模式144项与三格式AI/P长链，验证关闭路径；不能拿本次6例或历史66例替代。
3. 冻结最小合法内容partition合同，再做geometry→决策→系数顺序→writer/recon一致；不能把已有边界HORZ/VERT算成新功能。
4. 两项组合与性能质量、Clang/检测器/泄漏/最终源冻结全部完成后，才能发布0.0.5-m5。

任务包README、00/01/02/03、生产契约和总计划§9的当前修订共同采用上述有界范围。后续工具清单仍保留，历史报告不抹去。
