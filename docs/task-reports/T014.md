## 2. V1：错误宽高误报修复与回归

### 2.1 误报根因（M1 已复现）

旧 runner 用**调用者参数**推出期望字节数。`32×128` 的 4:2:0 紧排字节数 `32*128 + 2*16*64 = 6144`，恰好等于真 `64×64` 的 `64*64 + 2*32*32 = 6144`，于是“宽高全错但长度相同”被判 PASS。

### 2.2 修复方式

期望几何不再由参数或文件长度反推，而是从 decoder 自身报告读取：
- decoder 输出的 Y4M 头 `YUV4MPEG2 W<w> H<h> ... C<cs>`（真实编码宽高与色度）；
- decoder 诊断文本 `AVM_COLOR_INFO:cp=..,tc=..,mc=..`。
调用者的 `--width/--height/--frames/--bit-depth/--chroma` 变为**必须与 decoder 一致的断言**，不一致即 FAIL。

### 2.3 判别测试（任务书指定素材 `artifacts/T005/frame_min_64x64.bin`）

```powershell
# 真 64x64，声明 32x128（面积相同） => 必须 FAIL
python svt-av2\tools\run_matrix.py --check-bitstream ^
  --bitstream svt-av2\artifacts\T005\frame_min_64x64.bin ^
  --width 32 --height 128 --frames 1 --out-dir svt-av2\artifacts\T014\v1_wronggeom
# => exit 1 : FAIL: decoded geometry 64x64 != declared 32x128
```

实测：

| 命令 | 期望 | 实测 |
|---|---|---|
| `--width 32 --height 128` | FAIL | exit 1，`decoded geometry 64x64 != declared 32x128` |
| `--width 128 --height 32` | FAIL | exit 1，`decoded geometry 64x64 != declared 128x32` |
| `--width 64 --height 64` | PASS | exit 0，`6144 bytes (1 frames)` |
| `--metadata-probe` | 报告 64×64/420/8bit | `{"width":64,"height":64,"chroma":"420","bit_depth":8}` |

原始输出：`artifacts/T014/v1_wronggeom/`、`artifacts/T014/v1_wronggeom2/`、`artifacts/T014/v1_correct/`。
