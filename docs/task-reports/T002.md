## 5. runner（第 3 步）

`tools/run_matrix.py`：

| 模式 | 作用 | 退出码 |
|---|---|---|
| `--check-oracle` | 定位并打印 oracle 路径/SHA256 | 0 / 3 |
| `--smoke --entry <id>` | avmenc→avmdec，校验退出码、超时、输出非空、帧数、尺寸、raw 精确字节数 | 0/1/3 |
| `--check-bitstream --bitstream f --width W --height H --frames N` | 校验外部码流（供 T005） | 0/1/2/3 |
| `--self-test` | 负例：缺工具/非零退出/错误尺寸/截断码流 | 0/1 |

> 命名澄清（与 T006 对齐）：`--check-bitstream` 是 **runner 侧** 模式，不是 `compare_recon.py` 的参数。
> `compare_recon.py` 自身参数为 `--a --b --width --height --frames [--json|--text]`。T005 交付码流后，
> runner 以 `--check-bitstream` 调 avmdec 得到 expected raw，再调 `compare_recon.py` 与 actual（internal recon）比较。

**重要发现**：`avmdec` 对截断码流可能仍返回退出码 0，但报告 `0 decoded frames` 且 raw 为 0 字节。
runner 因此同时校验 decoder 报告的帧数与 raw 精确字节数——只看退出码会把截断码流误判为 PASS。
`--self-test` 用真实 oracle 覆盖了该场景：截断码流 → FAIL，完整码流 → PASS。

自测结果（真实运行）：

```
ok: missing decoder -> BLOCKED (exit 3)
ok: non-zero decoder -> FAIL (exit 1)
ok: wrong-size decoder output -> FAIL (exit 1)
ok: comparator identical -> exit 0
ok: comparator pixel mismatch -> exit 1
ok: comparator truncated actual -> exit 3
ok: truncated real bitstream -> FAIL (exit 1)
ok: intact real bitstream -> PASS (exit 0)
SELF-TEST PASS
```
