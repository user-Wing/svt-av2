## 2. 冻结配置与规范/AVM 依据

本轮只做 **8-bit 4:2:0、单线程、All-Intra、`base_q_idx = 100`**（契约 §0）。量化器状态由冻结流头唯一决定：

| 项 | 取值 | 依据 |
|---|---|---|
| `equal_ac_dc_q = 1` ⇒ `base_y_dc_delta_q = base_uv_dc_delta_q = 0`、`base_uv_dc_delta_q := base_uv_ac_delta_q = 0` | 全部 delta = 0 | `avm\av2\decoder\decodeframe.c`（`read_sequence_header_quant`）；契约 §0 |
| `y_dc_delta_q_enabled = 0`、`uv_dc/ac_delta_q_enabled = 0` | 全部 delta = 0 | 同上 |
| `using_qmatrix = 0` | 无量化矩阵 | `avm\av2\common\quant_common.c:170-174`；decoder 在该情形下用 `qmlevel = NUM_QM_LEVELS-1` 且 `iqmatrix == NULL`，`get_dqv()` 退化为 `dequant[!!coeff_idx]`（`decodetxb.c:142-144`） |
| TCQ | 关 | M2 未实现；`use_tcq_deadzone_boost = 0` ⇒ `abs_coeff_scale = dequant_ptr_scale = 1`（`av2_quantize.c:53-58`） |

⇒ 三平面、DC/AC 全部解析为 `qlookup(clamp(100, 1, 255)) = qlookup(100) = 704`。

`qlookup(100) = 704` 的逐步推导（**实表值，非近似**）：`idx = ((100-1)%24)+1 = 4`，`sh = (100-1)/24 = 4`，`table[4] = 44`，`44 << 4 = 704`。出处 `avm\av2\common\quant_common.c:26-30`（表）+ `:130-136`（周期扩展）。单测把 704 与派生量（round = 33、quant_fp = 11915、shift = 20、deadzone = 44）写成硬值交叉验证。

### 2.2 QP 范围：只支持 100（任务书要求显式说明）

`svt_av2_quant_params_init()` 对 `base_q_idx != 100` 返回 `SVT_AV2_QUANT_ERR_UNSUPPORTED`，**不是**静默 clamp。理由：公共 API 允许 0..255 只是**接口容量**，把 QP 100 的量化器配到 QP 150 的帧头上会产出一段 decoder 无法复现的码流。扩大范围须先经 00 确认并补对应 CDF/表测试（契约 §4）。

### 2.3 transform 尺寸/类型与 `tx_scale` 冻结（00 于 2026-10-07 裁决，取代 T009 的 8×8 提议）

**00 的上位裁决**（`[00][RULING]`）：冻结帧头硬编码 `tx_mode_select = 0` ⇒ `TX_MODE_LARGEST`，顶层 64×64 `PARTITION_NONE` 下 luma = **TX_64X64**、chroma = **TX_32X32**。T009 原提议的"8×8"不成立。我独立复核了该推导的每个环节，**全部属实**：

| 环节 | 位置 | 内容 |
|---|---|---|
| 帧头写 `tx_mode_select = 0` | `svt-av2\Source\Lib\Bitstream\frame_header.c:245-248` | 注释明写 `tx_mode_select = 0 -> TX_MODE_LARGEST` |
| `TX_MODE_LARGEST` → `TX_64X64` | `avm\av2\common\common_data.h:703-706` | `tx_mode_to_biggest_tx_size[] = {TX_4X4, TX_64X64, TX_64X64}` |
| luma 推导 | `avm\av2\common\blockd.h:2580-2589` + `common_data.h` | `max_txsize_rect_lookup[BLOCK_64X64] = TX_64X64`，`txsize_sqr_map[TX_64X64] ≤ TX_64X64` ⇒ 返回 `TX_64X64` |
| chroma 推导 | `avm\av2\common\blockd.h:3208-3215` | `av2_get_max_uv_txsize(BLOCK_64X64,1,1)` → `get_plane_block_size` → `ss_size_lookup[BLOCK_64X64][1][1] = BLOCK_32X32`（`blockd.h:2610-2617` + `ss_size_lookup` 表）→ `max_txsize_rect_lookup[BLOCK_32X32] = TX_32X32` |

⇒ **M2 首版实际使用的两个尺寸是 64×64（luma，tx_scale 2）与 32×32（chroma，tx_scale 1）。**

**完整 `tx_scale` 表**（`avm\av2\common\idct.c:761-765`，以代码为准；`tx_size_2d` 见 `common_data.h:613-616`）：

| 尺寸（pels） | `tx_scale = log_scale` |
|---|---|
| 4×4 / 4×8 / 8×4 / 8×8 / 4×16 / 16×4 / 8×16 / 16×8 / 16×16（≤256） | **0** |
| 16×32 / 32×16 / **32×32**（512 / 1024） | **1** |
| 32×64 / 64×32 / **64×64**（2048 / 4096） | **2** |

> **⚠ `tx_scale` 表按 `pels = w*h` 标称值计算，与"实际承载的系数个数"是两个无关问题。** 对 **TX_64X64**，`tx_scale = (4096>256)+(4096>1024) = 2` 无误，但 AVM 实际只承载 **1024** 个系数（`av2_get_max_eob`、编码 repack、逆变换入口均按 1024）—— 该 `count` 契约见 **§5.2.1（00 已裁决：count = min(w,32)*min(h,32)）**。`tx_scale` 取值只依赖 `w*h`，与 `count` 是否为 1024 无关，故本表不受影响。

`log_scale ≡ tx_scale`，唯一赋值点 `avm\av2\encoder\encodemb.c:819`（`qparam->log_scale = av2_get_tx_scale(tx_size)`）。

| 项 | 冻结值 | 依据 |

| transform 类型 | **DCT_DCT only**（二维可分离 DCT-II） | T009 / 00 |
| 本轮实际尺寸 | **TX_64X64（luma）+ TX_32X32（chroma）** | 00 裁决（上表复核） |
| `tx_scale = 0` 组 | shift 20、deadzone 44 | `av2_quantize.c:47`、`:109-111` |
| `tx_scale = 1` 组（32×32） | shift 19、deadzone 22 | 同上，`log_scale = 1` |
| `tx_scale = 2` 组（64×64） | shift 18、deadzone 11 | 同上，`log_scale = 2` |

**不得过度宣称（修订）**：T010 模块对 `tx_scale ∈ {0,1,2}` 全路径实现并有锚点测试（§4）。**T009 已于 2026-10-07 交付 pels > 256**（`SVT_AV2_TX_MAX_DIM` 由 16 改为 64，新增 TX_32X32/TX_64X64），故 32×32/64×64 的**真实 coeff 现已可产生**：tx_scale 1/2 的验证已由“合成 coeff + AVM 表达式逐点比对”（§5.1.6，3588 checks / 0 failures）升级为**真实 transform 输出驱动的端到端**（§5.1.8，`probe_t009_e2e.c`；`probe_coeff_range` 已覆盖 32×32/64×64）。**22× 余量仅 ≤16×16 成立**；实测 32×32 = 11.0×、64×64 = 5.5×（解析修正后 5.6×，见 §5.1.5/§5.1.8）。

### 组 B：forward deadzone——**实现错**（4 断言 + 1 级联计数）

| 失败 | 判定 |
|---|---|
| `test:417 q==1 (got 4)` / `:418 dq==88 (got 352)` | 实现正确（AVM 值即 4），**测试期望错** |

**实现错**：`svt_av2_quant_deadzone()` 原写作 `dequant >> (1 + log_scale)`，**漏掉 `+ QUANT_TABLE_BITS`**（=3），deadzone 宽了 2^3 = 8 倍。AVM 依据 `av2_quantize.c:109-111`（TCQ 关、无 qmatrix）：

```c
if (abs_coeff_scale *
        ((tran_high_t)abs_coeff << (1 + log_scale + QUANT_TABLE_BITS)) >=
    dequant_ptr_scale * (tran_high_t)dequant_ptr[rc01]) {
```

q=704、log_scale=0 的后果：

| | deadzone | coeff 44 | coeff 352 |
|---|---|---|---|
| AVM 正确 | `ceil(704/16)` = **44** | level 0 | level **4** |
| 被判定版本 | `704>>1` = 352 | 被强制 0 | level 4（巧合一致） |

所以 352 得到 level 4 是**正确的**，测试断言的 1 是错的；而实现把 44..351 这段本应为 level 1..3 的系数错误清零，即 `:701` 的 39 次不一致。

**同族实现错**：round 项未按 log_scale 缩放。AVM `av2_quantize.c:97-99` 用 `ROUND_POWER_OF_TWO(round_ptr[i], log_scale)`，被判定版本直接用 `round_QTX[i]`。log_scale=0 无差异，1/2 时偏置错误。已一并修正（`SvtAv2QuantCoeffs` 增 `log_scale` 字段）。

**测试期望错**：`test_forward_threshold` 原注释 "dequant >> 1 = 352, so |coeff| <= 351 must quantize to zero and 352 → level 1" 本身就是把错误实现的 deadzone 当规范。已按 AVM 改为四个锚点：43→0（<deadzone）、44→0（进入舍入但 `(44+33)*11915>>20=0`）、55→0、**56→1（首个非零）**、352→4，dq 为 `88*level`。`reference_forward_level()` 重写为完整 AVM 表达式（含上取整 deadzone 与 log_scale 缩放 round），不再复用被测实现。

### 本轮新增修复：forward `dqcoeff` 漏掉 `>> log_scale`（第 11 项，由 00 裁决的 32×32/64×64 锚点测试暴露）

补 00 要求的 tx_scale 1/2 锚点时，新测试 `test_forward_anchors_tx_scale_1_2()` 立即失败（6 处）：

```
FAIL:554 dq == first_dq   (got 88,   expected 44)      /* 32x32, log_scale 1 */
FAIL:558 dq == anchor_dq  (got 1408, expected 704)
FAIL:554 dq == first_dq   (got 88,   expected 22)      /* 64x64, log_scale 2 */
FAIL:558 dq == anchor_dq  (got 5632, expected 1408)
```

`level` 全部正确，只有 `dqcoeff` 偏大 2^log_scale 倍。定位到 `svt_av2_quantize_coeff_idx()`：它做了 `ROUND_POWER_OF_TWO(level*dequant, 3)` 后就返回，**漏掉了 AVM 紧接其后的 `>> log_scale`**。

AVM 依据 `avm\av2\encoder\av2_quantize.c:118-121`：

```c
const tran_low_t abs_dqcoeff =
    (tran_low_t)ROUND_POWER_OF_TWO_64((tran_high_t)abs_qcoeff * dequant,
                                      QUANT_TABLE_BITS) >>
    log_scale;
```

**先按 `QUANT_TABLE_BITS` 舍入，再右移 `log_scale`**（顺序不可交换：先移位会把奇数中间值提前截断）。

影响面：`log_scale == 0` 时 `>> 0` 是恒等，故此前 16×16 及以下的测试全绿；**但 32×32 / 64×64 —— 即 00 裁决的 M2 首版真实尺寸 —— dqcoeff 会整体偏大 2×/4×**，T012 用它会重建出错误残差。这是**实现错**，已修（`quantization.c:399-409`），并对 AVM 逐点验证（§5.1.6）。

**注意区分**：`svt_av2_dequant_coeff()` / `svt_av2_dequantize_block()` 的反量化路径**本来就有** `>>= params->tx_scale`（`quantization.c:234-235`），只有正向路径漏了。两条路径现在都在舍入后移位。

### 未纳入本轮修改的观察（仅登记，不静默改）

**decoder 的 `& 0xffffff` 掩码**：`decodetxb.c:621-629`、`:918-926` 在反量化前对 `dq_coeff_hp` 做 `& 0xffffff`。冻结配置下它是恒等操作（|level| ≤ 8191、dequant = 704 ⇒ 乘积 ≤ 5 766 464 < 2^24），故本轮实现未复刻，反量化测试与 decoder 表达式一致。一旦 QP 范围扩到 q≈255（dequant 可达 61440 ⇒ 8191×61440 ≈ 5.03e8 > 2^24），该掩码就非恒等，必须重新核对。这属于契约 §4 明确排除的"扩大 QP 范围"，**不在本轮修改**。

#### 5.1.2 舍入符号：已核实**无分歧**

T009 提醒其 `svt_av2_tx_round_shift(v,b) = (v + (1<<(b-1))) >> b` 是算术右移 floor，负数非 away-from-zero。经复核 **AVM 与两个模块在这一点上天然一致，无需对齐动作**：

`avm\avm_ports\mem.h:44-58` 有两个宏：

```c
L45 #define ROUND_POWER_OF_TWO(value, n)        (((value) + (((1 << (n)) >> 1))) >> (n))   /* "value >= 0" */
L48 #define ROUND_POWER_OF_TWO_SIGNED(value, n) (((value) < 0) ? -ROUND_POWER_OF_TWO(-(value), (n)) : ...)
L53 #define ROUND_POWER_OF_TWO_64(value, n)     (((value) + ((((int64_t)1 << (n)) >> 1))) >> (n))  /* "value >= 0" */
```

量化与反量化路径用的都是**非负版本**，因为操作数是**幅度**、符号在之后才加：

- 反量化 `decodetxb.c:918-926`：`level` 是无符号幅度（`:903` 才 `dc_val = sign ? -level : level`；`:923-925` 在 round+clamp **之后**才 `if (sign) dq_coeff = -dq_coeff;`）⇒ `ROUND_POWER_OF_TWO_64` 只见到非负值。
- 正量化 `av2_quantize.c:101-128`：`abs_coeff = (coeff ^ coeff_sign) - coeff_sign`，round 加在 `abs_coeff` 上，`qcoeff = (abs_qcoeff ^ coeff_sign) - coeff_sign` 还原符号。
- T010 结构相同（`quantization.c:366-391`），且 `svt_av2_round_power_of_two()` 与 `ROUND_POWER_OF_TWO_64` 逐字符同式；`test_dequant_rounding_sign` 对 level 1..200 断言 `dq(−L) == −dq(L)`。
- T009 的 `svt_av2_tx_round_shift` 对应 AVM `av2\av2\common\av2_txfm.h` 的 `round_shift()`（同一形式）。

⇒ 两侧都是"**幅度上 floor 舍入、符号对称**"，负 level / 负 coeff 在边界上自动一致。**不引入 away-from-zero，也不改动 704 / 11915 常数。**

- **不共用 buffer 是运行时强制的**：`qcoeff == dqcoeff` 直接返回 `SVT_AV2_QUANT_ERR_UNSUPPORTED`，不写任何输出。两者须为 `count` 个 `int32_t` 的独立缓冲，并在 T011 写完 syntax、T012 用完 dqcoeff 之前**同时有效**。本模块不持有指针、不分配内存。
- `dqcoeff` 由量化产生的同一 level 直接按 decoder 公式算出（同源），不是重量化一遍。
- 失败原子性：块内任一 level 超 8191 时整块返回 `LEVEL_OVERFLOW`，两数组都不写。
- 类型/范围：均 `int32_t`；`|qcoeff| ≤ 8191`；`dqcoeff` 已按 decoder 规则 clamp 到 `[-32768, 32767]`。
