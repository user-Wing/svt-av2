## 1. 目标与范围

实现 `svt-av2/tools/compare_recon.py`：对两个相同显式布局的 raw YUV 文件做
逐帧 / 逐 plane 的 bit-exact 比较，报告是否精确一致并定位首个 mismatch。

首版只支持**紧密排列的 8-bit 4:2:0**，显式给出 `--width/--height/--frames`。
不支持 10-bit、4:4:4、带 padding/stride 的内部缓冲；遇到一律显式报错，
不做静默裁剪、重采样、颜色转换或误差容限。

本任务只交付验证工具；不实现 encoder、BitWriter、decoder runner、Y4M parser。

## 3. 规范 / 契约依据

布局公式（仅 8-bit 420，偶数宽高）：

```
Y : width x height
U : (width/2) x (height/2)
V : (width/2) x (height/2)
frame_size  = width*height + 2*(width/2)*(height/2)
total_bytes = frame_size * frames
```

该公式**只用于本工具声明支持的格式**，不推广到未实现格式。

### CLI（已由 00 批准，见 `docs/m0-m1-contracts.md` 第 9 节；T002 已确认）

```
python tools/compare_recon.py --a <expected.raw> --b <actual.raw> \
       --width W --height H --frames N [--bit-depth 8] [--chroma 420] [--json|--text]
```

- `--a` = expected / reference（如 decoder 输出）
- `--b` = actual / tested（如 internal recon）
- `--json` 与 `--text` 互斥；`--text` 为默认。JSON 走 stdout；文本模式结论走 stdout，
  参数/文件类错误走 stderr。

### 退出码（已由 00 批准，见 `docs/m0-m1-contracts.md` 第 9 节）

| 码 | 含义 |
|---|---|
| 0 | 完全一致 |
| 1 | 像素不一致（长度合法） |
| 2 | 参数/用法错误（缺参、非正/奇数宽高、不支持的位深/色度） |
| 3 | 文件或长度错误（路径不存在、截断、多余字节、双侧等长但共同截断） |

### JSON 字段（固定）

```
schema_version, status, match, a, b, width, height, frames, layout,
expected_bytes, a_bytes, b_bytes,
first_mismatch{frame,plane,x,y,a_offset,b_offset,expected,actual},
mismatch_counts{Y,U,V,total}, sha256{a,b}, error
```

- `plane` ∈ {Y,U,V}；`x/y` 相对该 plane 起点；`a_offset/b_offset` 为文件字节偏移。
- `sha256` 只作辅助，**不替代**严格长度检查与差异定位。
