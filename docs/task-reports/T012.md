## 2. 冻结的重建链契约（契约 §6，本轮落盘）

每块**只允许**这一条链，`intra_frame.c:reconstruct_block()` 是唯一组装点：

```
source → prediction → residual → coeff → qcoeff → dqcoeff → inverse residual → clipped recon
```

| 环节 | 归属 | 本轮实现位置 |
|---|---|---|
| prediction（DC_PRED，邻居取自内部 recon） | T008 | `svt_av2_intra_reference_build` + `svt_av2_intra_dc_predict_flags` |
| residual = source − prediction（`int16_t`） | T008 | `svt_av2_residual_compute` |
| coeff / qcoeff / dqcoeff / inverse residual | T009+T010 | 经接缝 `SvtAv2IntraTransformPath`（见 §4、§5.5） |
| `Clip3(0,255, prediction + inverse_residual)` 且**写回即邻居更新** | T012 | `svt_av2_recon_write_block` |
| 导出紧密 8-bit 4:2:0 raw | T007 | 仅**调用** `svt_av2_picture_export_raw` |

### 2.1 预测写入位置（本轮唯一正确性要点）

prediction **原地写进 recon 平面**的块位置（AVM 顺序），随后 residual 从该位置读回，
最后由 clipped write 原地覆盖。这样：
- 不需要第二块 prediction 缓冲；
- "prediction 是按邻居算的、不是复制 source"这一点由写位置本身保证；
- 块只有在 clipped write 之后才成为后续块的合法邻居。

## 3. 导出契约（任务书要求，契约 §6）

- 导出**不重写** raw 打包：`svt_av2_recon_export_raw` 内部调用 T007 的**唯一**原语
  `svt_av2_picture_export_raw`，本模块只补 `SvtAv2ReconExport` 描述符。
- 布局：紧密 `Y‖U‖V`，**移除全部 padding**；长度 = `W*H + 2*(W/2)*(H/2)`。
- 帧尺寸与帧序号由描述符携带（raw 流自身不含这些信息）。
- 与 `tools\compare_recon.py` 的期望布局一致。

## 4. 变换接缝：失败关闭，不占位（任务书硬性边界）

帧 core 把变换/量化做成显式函数指针接缝
`SvtAv2IntraTransformPath{forward, inverse, name, user}`：

- 生产调用方传真实 T009/T010 组成的 path（**现已由 `transform_path.{h,c}` 提供**，见 §5.5）。
- **`forward`/`inverse` 任一为 NULL → `svt_av2_intra_frame_encode` 立即返回
  `SVT_AV2_ERROR_UNSUPPORTED`**，绝不静默把 source 写进 recon，也绝不当零残差处理。
  `test_fails_closed_without_transform_path` 断言该行为（含"只给 forward 不给 inverse"的半成品）。
- `block_hook` 返回非零（例如 T011 syntax 写不下去）→ 帧返回 `SVT_AV2_ERROR_INVALID_STATE`，
  不报成功。`test_hook_failure_aborts` 覆盖。

`test_intra_frame` 内的 scaffolding path（直通变换 + 真实整数 deadzone 量化器）**只用于帧 core
自身的单测**，不是 T009/T010 的实现，其数值不声称符合 AV2，也不据此断言码流或 decoder 一致。
真实 T009/T010 的验证在 `test_transform_path` 与 §5.5/§5.6。

### 5.4 邻居可用性硬前置条件（与 T008 §3 联合复核）

T008 的接口说明 §3 明确：**tile / superblock 边界不是图像边界**，若某块在图像内部
但因 tile/未重建而无可用前驱，T012 必须显式传 `have_left/have_above = 0`。

本轮帧 core 的可用性**取自 T007 的单一事实来源** `svt_av2_block_neighbors`
（`above_valid = y > 0`、`left_valid = x > 0`），不再在 core 内自行推导 `x > 0`，
以免 T011 引入编码边界时两处策略漂移。该配对**只在**"raster 顺序前驱即真实可用"时成立；
冻结配置（单 tile、SB 行主序）恰好满足。

本轮把它做成**可失败的断言**：

- `intra_frame.h` 把该条件写成硬前置条件，并指明接缝（已调用的就是 T008 的 `*_flags` 入口，
  切换成 tile-aware flags 是本地改动、非 API 变更）。
- `test_neighbour_availability_is_raster_order`（176×144，通过 block hook 记录逐样点重建覆盖）断言：
  - core 声称 `have_left`（`x > 0`）时，`(x-1, y)` 必须已被本帧更早的块重建；
  - core 声称 `have_above`（`y > 0`）时，`(x, y-1)` 必须已被本帧更早的块重建；
  - core 的行动可用性 == T007 `svt_av2_block_neighbors` 的判定（`flag_mismatch == 0`）；
  - 三个平面每个可见样点被恰好覆盖一次（hook 次数 == `3 * luma_blocks`，掩码全 1）。

**非空洞性验证（探针）**：为证明断言会真正失败而非恒真，临时让 coverage hook 跳过标记第一个块
（模拟 tile 空洞，等价于"raster 前驱不可用却传了 `have_left=1`"），结果
`test_intra_frame: 62820 checks, 4098 failures`，退出码 1。随后已还原探针；当前文件 hash
见 §1，复跑结果为 0 failures。探针**未进入交付物**。

的 `-Wmaybe-uninitialized` 无法透过"循环里的 `memcpy`"看到该前缀覆盖，故误报。

> 更正 T016 建议里的一处方向笔误：其原文称调用点 `kw >= block_w`、`kh >= block_h`。
> 事实相反——`kw = min(block_w, 32)`，故 64×64 时 `kw*kh = 1024 < 4096 = block_w*block_h`。
> 但**结论不变**：消费者读的就是 `kw*kh`，gather 写的也是 `kw*kh`，二者恒等，无未初始化读。
> 这一条已由 §5.13 的探针 1 号断言（11 个几何对全过）把"恒等"从叙述升级为**会失败的门限**。

`packed[0 .. count)` —— 正是被读的前缀，且是 GCC 11 能跨调用跟住的形态：

```c
static void path_gather_coeff(const int32_t* src, uint32_t stride,
                              uint32_t kw, uint32_t kh, int32_t* packed) {
    const size_t count = (size_t)kw * (size_t)kh;
    for (size_t i = 0; i < count; ++i) {

}
```

## 7. 给 T013 的接口说明（已单独发消息，抄送 00）

见 `Source\Lib\Encoder\intra_frame.h` 与 `Source\Lib\Reconstruction\reconstruction.h`。调用形态：

```c
/* 每帧一次：分配 recon（T007）与 scratch，编码，导出。 */
SvtAv2FrameBuffer internal_src, internal_recon;          /* 库拥有，一次 calloc */

svt_av2_recon_export_raw(&internal_recon, out, cap, &written);  /* 内部调 T007 唯一原语 */
```

要点：
- `block_hook` 里 T011 读的 `scratch->qcoeff`/`dqcoeff` 是 **T009 原生打包网格**：
  **行 stride `min(w,32)`、长度 `min(w,32)*min(h,32)`**（64×64 → 1024 项，**不是** 4096）。
  **不是** `scratch->stride`，也**不是** `block->w` 宽的普通光栅——这正是 T011 的 scan 建的网格
  （`coeff_syntax.c` 的 `adjusted_dim = min(d,32)`）。**T011/T013 零改动**即可消费。
  （§5.11：我此前说"普通光栅"是错的，已按 00 裁定方案 A 更正；**删除了那一层转换**。）
- `config.sb_size` 只接受 64/128/256（T007 约束）。**本轮只用 `sb_size = 64`**
  （顶层 `PARTITION_NONE`，luma 64×64 → TX_64X64、chroma 32×32 → TX_32X32，已可编码，见 §5.5/§5.9）。
  `sb_size=128/256` 会产出 128/256 的块，**T009 变换不了**（支持集上限 64）；
  如需大 SB 须先决定细分策略（本轮未在 T012 内做细分）。
- source 与 recon 必须是两个独立缓冲。**把公共 `SvtAv2Picture` 拷进内部 assigned frame 用
  `svt_av2_picture_copy_from_view`**（不是 `copy_in`）——`copy_in` 两端都必须是
  `SvtAv2FrameBuffer`，公共 `SvtAv2Picture` 是借出视图、`buffer == NULL`，不能当它的 source。
  桥接（T007 已实现，**不需要新接口**）：
  ```c
  SvtAv2BorrowedView view;
  svt_av2_picture_view(&view, caller.planes, caller.strides, caller.width, caller.height);
  svt_av2_picture_copy_from_view(&internal_src, &view);   /* 调用期内读取，不保留指针 */
  ```
  见 §5.12。caller 指针不得跨调用保留。
