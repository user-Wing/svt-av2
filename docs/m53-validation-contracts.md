本轮开放非无损CQP userQP1..255；8bit实际qindex=QP，10bit沿用QP+48，取值49..303。默认仍QP100，QP0无损不在范围内。原三格式、AI/P、两工具四组合、最大1080p、8倍数尺寸及单线程限制保持。必须补齐全部可达CDF初始化组、量化查表和解码器一致的系数重建，不能只删入口guard；QP100四组合相对M5.2流与内部重建指纹必须保持。

用户明确后续只做CQP与CRF。取消CBR、2-pass以及其他独立码率目标模式（含VBR/VBV模式）的开发门槛；未来CRF以内容复杂度自适应的质量/体积控制为目标，不承诺未经测量的全局最佳。此为项目产品取舍，不以“其他模式不能分配可变帧码量”作为技术论据。CRF仍在M9，不在本轮伪装实现。

## 验收

1. 所有255QP在8/10bit及真实TX下的独立量化/逆量化测试，极值、符号、解码器mask/clip和整数溢出检查；实际跨CDF边界和高幅系数流由固定AVM解码，内部重建必须逐样本一致。
2. 三格式AI/P和四组合在多个QP上编解码，包含低/高端及两位深不同CDF分界；QP100回归冻结M5.2、默认全关回归M4。公共API非法QP、容量重试/所有权/PTS/EOS继续成立。
3. 批量脚本冻结素材、编码器、固定decoder、VMAF工具/模型及任务配置hash；中断后只复用指纹匹配且产物完整的PASS项，逐项原子落盘，重复运行不误用陈旧结果。每任务有timeout、命令、退出码和日志，失败不能计PASS。
4. 测量编码wall time/FPS、采样峰值RSS、码量和Y/U/V MSE/PSNR；适用时VMAF固定模型和输入转换规则。VMAF是外部评分，不是编码优化目标，也不能代替色度PSNR。原始输入与重建用于质量，内部与独立decoder逐样本对比用于正确性。
5. 至少4个质量点才能计算多点BD-rate，记录插值方法、重叠区间和无效曲线原因；质量点不足、非单调、无重叠时N/A。并行批测吞吐与单进程速度测量分开，性能任务默认jobs1，重复3次。
6. Windows/GCC/Clang严格构建、跨平台指纹、ASan/UBSan/LSan真实多QP路径和长链、Valgrind，最后冻结源与产物。长时间大规模运行可在脚本中独立完成；未完成的实际运行不能写DONE，不因脚本已交付宣称数天测试已通过。

VMAF模型、额外运行依赖只新增到本轮目录。完整CRF、RD框架、preset策略、编码器内部多线程仍分别是M9、M6、M7、M8；批量脚本多进程并行不等于编码器内部多线程。
