## 一次编码

在C:\Private\ffmpeg-native\deps-full\AV2\svt-av2执行：

```powershell
.\build\m53-root\Windows-final\bin\SvtAv2EncApp.exe --input input.y4m --output output.av2 --export-recon recon.yuv --qp 160 --pred-structure low-delay-p --intra-select adaptive --partition-select adaptive
```

intra-select=dc/adaptive，partition-select=fixed/adaptive，共4工具组合；乘AI/P和3格式为24种，乘255个QP为6120种基本配置。preset枚举尚无不同搜索策略，不计入有效组合。范围仍限8bit420、10bit420/444，尺寸为8倍数且至1920×1080，单编码进程单线程。

## 准备素材

Python需要NumPy。本机Python3.11与build/m5-root/pydeps的NumPy2.4.6已验证。交互执行工具前设置：

```powershell
$env:PYTHONPATH = (Resolve-Path build/m5-root/pydeps).Path
python tools/m53_corpus.py --out-dir artifacts/my-corpus --size 1280x720 --frames 128
```

输出8类可复现合成素材×3格式及corpus.json；合成素材用于控制条件和压力测试，不能替代真实视频上的主观质量判断。也可自己提供Y4M文件，并写UTF-8 JSON：

```json
[
  {"path": "D:/videos/anime-10bit420.y4m", "scene": "anime"},
  {"path": "D:/videos/grain-10bit444.y4m", "scene": "grain"}
]
```

相对路径以corpus.json所在目录为基准。先在外部完成剪辑或格式转换，运行期间保留素材不变。当前生成器和编码器不支持4K。

## 后台长测

```powershell
.\tools\Start-M53Batch.ps1 -Corpus artifacts/my-corpus/corpus.json -RunRoot artifacts/my-campaign -Qps '40,100,160,220' -Jobs 4 -Repeats 3 -CrossPlatform
```

该命令创建任务私有的编码器、固定decoder、FFmpeg、VMAF模型和Python脚本快照，以隐藏窗口启动独立Python进程，写出PID及日志后返回。运行不依赖AI会话继续在线。默认app为build/m53-root/Windows-final/bin/SvtAv2EncApp.exe，decoder为固定AVM，FFmpeg取PATH，模型为artifacts/m53-root/deps/vmaf_v0.6.1.json；可用-App/-Decoder/-FFmpeg/-VmafModel/-Python明确指定。

指定-CrossPlatform时，任务先保存本机WSL的GCC/Clang/SAN编码器快照；Windows批量编码、解码/VMAF与独立审计成功后，依次自动重放GCC、Clang和ASan/UBSan/LSan，比较完整码流及内部重建SHA。要求WSL发行版ARXChem-Ubuntu-22.04-WSL1及/root/svt-av2-m53/{GCC,Clang,SAN}/bin/SvtAv2EncApp已由tools/build_m53_linux.sh构建。不指定时仅跑Windows。并行进程不等于编码器内部多线程。

速度测量用-Jobs 1，默认-Repeats 3取中位数。多任务并行的耗时受竞争影响，只能视为该批测环境的数据；即使Jobs1也应避免同时运行其他重任务。--timeout默认86400秒，作用于每次命令而非整个campaign；超大任务可直接用Python CLI修改。

VMAF模型来自Netflix/vmaf的v3.0.0 tag下model/vmaf_v0.6.1.json，SHA256为5950d61fa1f861bd45d8149d80539ed9f3376cfc2495b8f0fa8e9f57cb131ee3。固定模型用于结果可比，并不声称是最新或适合所有内容的模型。FFmpeg/libvmaf在CPU上评分；两路均重置PTS并转换为yuv420p10le。444评分因此不能代表原始444色度质量，Y/U/V PSNR/MSE仍在原格式逐样本计算。小尺寸合成流主要验证评测链路，不作为主观质量结论。

## 查看状态与恢复

```powershell
Get-Content artifacts/my-campaign/campaign-status.json
Get-Content artifacts/my-campaign/windows.campaign.log -Tail 10
```

campaign-status.json标明RUNNING及阶段、PASS或FAIL。results/summary.json只代表Windows批测，不能替代整个campaign状态；GCC/Clang/SAN目录另存各平台证据。不要根据旧acceptance.json或日志末尾几个PASS判断整批通过。

关闭AI聊天不会停止独立进程。进程崩溃、重启后确认旧任务进程和本批编码子进程已退出，再执行：

```powershell
.\tools\Start-M53Batch.ps1 -Corpus artifacts/my-corpus/corpus.json -RunRoot artifacts/my-campaign -Resume
```

恢复使用保存的配置和快照。已完成且源/工具/模型/配置/保留产物hash匹配的项直接复用，损坏或未完成项重跑；显式传入不同QP、Jobs、Repeats或Corpus会拒绝，需新建RunRoot。Windows任务按attempt新目录保存失败现场；跨平台重放使用固定索引目录重新生成未完成项。协调锁防止两个进程同时操作一个campaign。

成功项清除大体积内部raw与独立解码Y4M，只保留首轮码流、VMAF JSON、日志和逐帧hash。失败现场会保留，重复失败可能继续占盘。启动和每项编码前都会估算可用空间；预留约Jobs×(4×帧数×raw单帧字节+16MiB)，持久码流还需额外空间。例如1080p10bit444/1000帧，仅两份raw就约24.9GB/任务，应减小Jobs或选择大容量盘。不要删除或修改仍在运行的素材、快照、结果文件。

## 完成后验收

```powershell
python tools/audit_m53_batch.py --out-dir artifacts/my-campaign/results
```

审计检查完整任务覆盖、依赖与保留产物hash、重复编码次数、解码/VMAF帧数和指标一致性。RUNNING、失败、重复/缺失任务、损坏流、改动的模型或依赖均不能PASS。CrossPlatform campaign还应检查campaign-status=PASS及三个平台summary=PASS，最后由阶段集成器结合源码清单、完整CTest和泄漏证据验收；脚本跑完不自动发布正式M5。

summary.json记录相对全关的PSNR-Y和VMAF BD-rate，采用log(码量)上的保单调PCHIP积分和共同质量区间。至少4点；重复/非单调质量点、缺指标或无重叠区间明确N/A。299组独立随机曲线与SciPy PchipInterpolator积分已核对。BD-rate负值表示在该质量指标的共同区间内码量较低，不保证另一指标或主观观感同样改善。

原先scenes768的全局cubic汇总在VMAF饱和处发生数值溢出，失败目录与曲线已保留；修复后使用全新scenes768-r2重跑并审计通过，没有绕过指纹限制复用旧目录。所有实际运行结果以各自summary/audit和源码指纹为准。
